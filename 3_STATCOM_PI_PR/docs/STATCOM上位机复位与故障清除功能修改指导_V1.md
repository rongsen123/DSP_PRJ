# STATCOM上位机复位与故障清除功能修改指导 V1

## 1. 文档用途

本文档用于指导其他AI修改以下上位机工程：

`F:\DSP\SST_PRJ\3_STATCOM_PI_PR\docs\statcom_host`

本轮目标是在不破坏现有START/STOP和周期监控功能的前提下，增加：

1. 清除CPLD锁存故障；
2. 清故障操作联锁、二次确认、执行状态跟踪和事件日志；
3. 修复当前单槽请求机制可能覆盖STOP或清故障命令的问题。

当前DSP、CPLD与上位机已经配套实现清故障、复位CPLD和复位DSP。协议版本为`0x0102`；维护动作均使用FC06密钥写入并受STOP联锁。

## 2. 当前系统事实

### 2.1 通信结构

```text
上位机Modbus主站
  └─ SCI-B，115200 bit/s，8N1
      └─ DSP Modbus从站，地址2
          └─ SCI-A，115200 bit/s，8N1
              └─ CPLD Modbus从站，地址1
```

上位机不能直接访问CPLD。所有CPLD维护命令必须先写入DSP，再由DSP通过SCI-A转发。

### 2.2 当前已有命令

DSP和CPLD当前实现以下保持寄存器：

- `0x0000`：STOP；
- `0x0001`：START。
- `0x0101=A55A`：在STOP条件下请求清除CPLD已经消失的锁存故障。

上位机当前也只有START和STOP按钮。

### 2.3 当前复位能力

- DSP已实现清故障和CPLD复位请求的SCI-A转发状态机；
- CPLD故障锁存器的清除输入已连接Modbus单周期脉冲；
- CPLD在完整回复`0x0102`后复位UART、Modbus、ADC、温度监测和故障锁存逻辑；
- DSP在完整回复`0x0103`后通过看门狗复位；两种复位均保持功率输出硬封锁。

## 3. 必须区分的三种操作

### 3.1 清除CPLD锁存故障

这是日常调试最需要的功能，不等于复位整个CPLD。

清除时只能删除已经消失的故障。仍然存在的硬件故障必须立即重新保持，不能被上位机强制抹掉。

### 3.2 复位CPLD

用于恢复CPLD UART、Modbus状态机、ADC采集状态机和通信状态。复位期间所有PWM和继电器输出必须保持安全态。

### 3.3 复位DSP

用于恢复DSP软件状态机。DSP必须先回复命令已接受，等待SCI-B发送完成，再通过看门狗或受控软件复位执行。复位后运行命令必须恢复为STOP。

主界面只应直接提供“清除锁存故障”。“复位CPLD”和“复位DSP”必须放在维护区域，避免误操作。

## 4. 建议的新增寄存器协议

### 4.1 上位机访问DSP从站2

| 地址 | 功能 | 写入密钥 | 功能码 | 属性 |
|---|---|---:|---|---|
| `0100` | STOP/START | `0000/0001` | FC06，保留现有FC03/FC10 | 保持型命令 |
| `0101` | 清除CPLD锁存故障 | `A55A` | FC06 | 单次动作 |
| `0102` | 复位CPLD | `C33C` | FC06 | 单次维护动作 |
| `0103` | 复位DSP | `D55D` | FC06 | 单次维护动作 |

动作寄存器不保存密钥值。正确密钥只产生一次待执行事件；错误值返回Modbus异常`03`，未实现地址返回异常`02`。

### 4.2 DSP访问CPLD从站1

| 地址 | 功能 | 写入密钥 | 功能码 |
|---|---|---:|---|
| `0100` | STOP/START回显 | `0000/0001` | FC06 |
| `0101` | 清除锁存故障 | `A55A` | FC06 |
| `0102` | CPLD软复位 | `C33C` | FC06 |

DSP复位只在DSP本机执行，不转发到CPLD。

### 4.3 已知测试帧

CRC为Modbus CRC16，低字节先发送：

| 操作 | 请求帧 |
|---|---|
| 上位机请求DSP清除CPLD故障 | `02 06 01 01 A5 5A 22 AE` |
| 上位机请求复位CPLD | `02 06 01 02 C3 3C 79 24` |
| 上位机请求复位DSP | `02 06 01 03 D5 5D E7 6C` |
| DSP请求CPLD清除故障 | `01 06 01 01 A5 5A 22 9D` |
| DSP请求CPLD软复位 | `01 06 01 02 C3 3C 79 17` |

上位机必须通过现有报文构造函数计算CRC，禁止在业务代码里直接写死完整帧。

## 5. 固件兼容性要求

清故障和复位命令实现后，DSP和CPLD协议版本为`0x0102`。

上位机连接后应读取DSP输入寄存器`0x0000`：

- 版本小于`0x0101`：清故障按钮禁用，并显示“当前DSP/CPLD固件不支持远程清故障”；
- 版本等于或高于`0x0101`：根据在线状态和STOP联锁决定清故障按钮是否可用；
- CPLD/DSP复位按钮仅在协议版本不低于`0x0102`且满足STOP联锁时启用；
- 不得因为FC06收到异常`02`就显示执行成功。

真实串口模式必须保留协议版本、STOP和链路状态检查；FC06回显表示命令已受理，最终结果还需通过CPLD重连或DSP运行时间归零验证。

## 6. 上位机界面修改

### 6.1 故障页增加“清除CPLD锁存故障”

在“故障与事件”页增加一个明显但不危险的按钮：

`清除CPLD锁存故障`

按钮启用条件必须同时满足：

1. 串口已连接；
2. DSP协议版本不低于`0x0101`；
3. DSP-CPLD链路在线；
4. DSP请求命令为STOP；
5. CPLD命令回显为STOP；
6. 当前没有其他维护操作正在执行。

点击后弹出确认框，明确提示：

> 该操作只清除已经消失的锁存故障。仍然存在的硬件故障将继续保持，不会解除PWM安全封锁。

### 6.2 增加“维护操作”区域

在故障页或诊断页增加默认折叠的“高级维护”区域，包含：

- 复位CPLD；
- 复位DSP；
- 最近一次维护操作；
- 操作执行状态；
- 操作开始时间和结果文本。

“复位CPLD”确认框要求用户输入：

`RESET CPLD`

“复位DSP”确认框要求用户输入：

`RESET DSP`

输入不完全一致时不允许执行。

### 6.3 操作期间界面联锁

维护操作开始后：

- 禁用START；
- 禁用其他维护按钮；
- STOP保持可用且优先级最高；
- 显示“命令发送中/等待CPLD重连/等待DSP重启”等明确状态；
- 记录请求帧、响应帧、异常码、超时和最终结果。

## 7. 上位机通信线程必须修改

### 7.1 当前问题

`communication/serial_worker.py`当前只使用一个`_pending_request`变量。周期FC04轮询和按钮命令都写入这个变量，因此100 ms周期读取存在覆盖尚未处理的STOP、清故障或复位命令的竞态。

代码注释中的“STOP具有优先级”目前没有得到数据结构保证。

### 7.2 必须改为线程安全优先队列

建议使用`queue.PriorityQueue`，每个队列元素至少包含：

```python
(priority, sequence_number, request_type, payload)
```

优先级建议：

| 优先级 | 请求 |
|---:|---|
| 0 | STOP |
| 1 | 清故障、复位CPLD、复位DSP |
| 2 | START |
| 10 | FC03手动读取 |
| 20 | 周期FC04读取 |

要求：

- 同一时刻只允许一个Modbus事务在途；
- 周期轮询不得覆盖或插队维护命令；
- 队列中已经存在周期FC04时，不得重复堆积周期读取；
- STOP到达时可以丢弃尚未发送的START，但不能破坏正在发送的帧；
- 使用单调递增序号保证相同优先级下顺序稳定；
- UI线程不得直接操作串口对象。

## 9. 动作状态机

### 9.1 清除CPLD锁存故障

```text
检查连接和协议版本
→ 确认DSP请求值=STOP
→ 确认CPLD回显=STOP
→ FC06写DSP 0101=A55A
→ 收到完整原帧回显
→ 连续读取输入寄存器
→ 故障位清除：成功
→ 故障位仍在：提示“故障源仍存在或清除失败”
```

上位机不能仅根据FC06回显判断故障已经消失；FC06回显只表示DSP接受了请求。

### 9.2 复位CPLD

```text
STOP双重确认
→ FC06写DSP 0102=C33C
→ DSP接受并转发
→ CPLD回复DSP后延迟执行软复位
→ DSP-CPLD链路短暂离线
→ 规定时间内重新在线
→ CPLD命令回显为STOP
→ 重新读取故障、ADC和温度状态
→ 成功
```

建议上位机等待CPLD重连超时为3秒。没有观察到离线再在线时，不应直接宣告复位成功。

### 9.3 复位DSP

```text
STOP双重确认
→ FC06写DSP 0103=D55D
→ DSP发送完响应后延迟复位
→ 上位机允许出现预期通信中断
→ 自动尝试重新建立通信
→ 读取协议版本
→ 确认DSP uptime明显减小
→ 确认请求命令和CPLD回显均为STOP
→ 成功
```

建议等待DSP恢复超时为5秒。重新连接后uptime没有减小，不能显示复位成功。

## 10. 安全要求

1. 清故障和复位前必须先STOP；
2. 既要检查DSP请求值，也要检查CPLD回显；
3. 链路离线时禁止清故障和CPLD复位；
4. 维护动作期间禁止START；
5. STOP永远具有最高队列优先级；
6. 任何异常响应、CRC错误或超时都不能显示成功；
7. 清故障后必须重新读取故障位确认；
8. 故障源仍存在时，界面必须显示“故障仍存在”，不能显示“已清除”；
9. DSP/CPLD复位后默认状态必须为STOP；
10. 上位机按钮不能解除CPLD当前的PWM和继电器硬封锁。

## 11. 单元测试和验收

### 11.1 协议测试

- 三个新增FC06请求的CRC测试；
- 正确回显解析；
- 错误密钥返回异常`03`；
- 旧固件地址返回异常`02`；
- 响应地址、寄存器或值不一致时判失败；
- CRC错误和超时分别计数。

### 11.2 队列测试

- 周期FC04不得覆盖STOP；
- 周期FC04不得覆盖清故障或复位；
- STOP应排在尚未发送的START之前；
- 多个周期读取不能无限堆积；
- 任一时刻只存在一个串口事务。

### 11.3 清故障测试

- 无活动故障时清除成功；
- 已消失的锁存故障能够清除；
- 故障源仍存在时清除后继续置位；
- CPLD离线时按钮不可用；
- START状态下按钮不可用；
- FC06回显成功但故障位未清时不得显示成功。

### 11.4 CPLD复位测试

- 必须输入`RESET CPLD`；
- 观察到链路离线再在线；
- 重连后命令回显为STOP；
- 超时未恢复时显示失败；
- 复位期间START按钮不可用。

### 11.5 DSP复位测试

- 必须输入`RESET DSP`；
- 允许预期串口超时；
- 自动重连成功；
- uptime重新从小值开始；
- 请求值和CPLD回显均恢复STOP；
- 超时未恢复时显示失败并保留错误日志。

### 11.6 旧固件兼容测试

- 连接协议版本`0x0100`时，三个维护按钮必须禁用；
- 界面仍能正常进行23寄存器读取和START/STOP测试；
- 不允许通过隐藏快捷键绕过版本检查。
